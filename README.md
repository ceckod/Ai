# Helfi Plastics — приложение

Скелет за уеб приложението на Helfi Plastics. Инсталируем е като PWA и има
готова верига за генериране на Android APK от самия сайт (TWA — Trusted Web
Activity), без потребителят да отваря браузър.

Ще расте постепенно — модул по модул (виж секцията "Модули" в `index.html`).

## Данни: централизирани, само за четене за посетителите

Приложението **няма** база данни/сървър засега — и не е нужна. Работи изцяло
статично, но данните са организирани централизирано, а не разпръснати из
JS файловете:

- **`data/products-data.json`** е ЕДИНСТВЕНИЯТ източник на истина за
  каталога с артикули (опаковка, производствен цикъл, история на записите).
  Него го поддържаш само ти, като администратор.
- Всеки посетител на сайта зарежда този файл и вижда каталога, диспечера и
  калкулатора **само за четене** — може да разглежда, да търси артикул, да
  "симулира" машина + бутилка в Диспечера/Калкулатора и да вижда какво би
  се произвело, но нищо от това не се записва никъде (нито при него, нито
  централно). Графикът на смени (`smeni.html`) е чиста сметка по дата — също
  не пази нищо.
- Единственият модул, който **пише** данни, е скрит "админ режим" в
  `produkti.html` — виж по-долу.
- Всичко минава през един файл — `js/data-store.js` — който по-късно, когато
  решиш да минеш на Firebase/друга база, е единственото място, което трябва
  да се преработи. Останалите страници изобщо не знаят откъде идват данните.

### Скрит админ режим (само за теб)

Няма login екран за обикновените посетители — това е нарочно. Вместо това,
на `produkti.html`, само ти знаеш как да влезеш в режим на редакция:

1. Кликни 5 пъти бързо върху заглавието "Продукти" горе на страницата
   (или отвори `produkti.html#admin`).
2. Въведи ПИН-а (по подразбиране `4271` — виж и смени го в
   `js/data-store.js` → константата `ADMIN_PIN`, преди да пуснеш сайта
   истински, за да не остане стандартната стойност).
3. След отключване виждаш пълния редактор (добавяне на артикули, опаковка,
   цикъл, записи от производство и т.н.) — точно както преди. Редакциите се
   пазят като **чернова само в браузъра на това устройство**, докато не ги
   публикуваш.

⚠️ Това е "скрита врата", не истинска защита — ПИН-ът се проверява в
браузъра, така че технически защитен потребител би могъл да го открие в
кода. За вътрешен инструмент, използван само от теб, това е достатъчно;
не въвеждай през него нищо, което не искаш да е публично видимо в кода.

### Как публикуваш промените, за да ги видят всички

Когато си доволен от черновата в админ режим:

1. Натисни **"⬇ Изтегли за публикуване"** — изтегля се нов
   `products-data.json`.
2. В GitHub отвори папка `data/` в проекта → **Add file → Upload files** →
   пусни изтегления `products-data.json` (ще замести стария) → Commit.
   (Или го качи през целия `_upload/` zip поток по-долу, ако публикуваш
   няколко файла наведнъж.)
3. Готово — при следващия `push` сайтът се обновява автоматично и всички
   посетители виждат новите данни (все така само за четене).

Бутонът **"Отхвърли черновата"** връща локалните ти редакции към последно
публикуваните данни (полезно ако объркаш нещо). Бутонът **"Изход от админ"**
заключва режима на редакция на устройството ти (черновата остава пазена, ще
я видиш пак при следващо отключване).

## Структура

```
index.html              главна страница
css/style.css            стилове
data/products-data.json  ЕДИНСТВЕНИЯТ източник на данни за каталога (виж горе)
js/data-store.js         централен слой за достъп до данните + скрит админ режим
js/app.js                логика + регистрация на service worker
manifest.json             PWA манифест (име, икони, цветове)
service-worker.js         offline кеш
icons/                    икони за PWA/Android
.well-known/assetlinks.json  верификация за Android TWA (виж по-долу)
twa-manifest.json         конфигурация за Bubblewrap (Android build)
.github/workflows/
  deploy-pages.yml         автоматичен deploy към GitHub Pages при push
  build-apk.yml            генерира .apk файл (ръчно или при release)
```

## 1. Първоначален setup

1. Създай ново GitHub repo (напр. `helfi-app`) и качи тези файлове.
2. В repo → **Settings → Pages** → Source: избери **GitHub Actions**.
3. При push към `main` сайтът автоматично се качва на:
   `https://YOUR-USERNAME.github.io/helfi-app/`

## 2. Постепенно ъпгрейдване

Всеки нов push към `main` автоматично обновява живия сайт (workflow-ът
`deploy-pages.yml`). Можеш да добавяш модули един по един в `index.html` /
`css/style.css` / `js/app.js`, без да чупиш останалото.

### Бърз ъпдейт с един zip файл

Не се налага да разархивираш и качваш файлове един по един. Вместо това:

1. GitHub → папка `_upload/` → **Add file → Upload files**.
2. Качи целия нов `.zip` (напр. от Claude) и направи commit.
3. Workflow-ът `unpack-upload.yml` сам го разархивира по правилните
   места, трие zip-а и пуска нов commit — сайтът се обновява автоматично
   след това (виж раздел **Actions** в repo-то за прогреса).

## 3. Android приложение (APK)

Това изисква **една еднократна ръчна стъпка** — генериране на подписващ
ключ (keystore). Без нея всеки APK build ще излиза с различен подпис и
Android ще го третира като различно приложение всеки път.

### Еднократно, локално на твоя компютър:

```bash
npm install -g @bubblewrap/cli
keytool -genkey -v -keystore android.keystore -alias helfi-key \
  -keyalg RSA -keysize 2048 -validity 10000
```

Ще те пита за парола на keystore-а и за данни (име, организация) — просто
попълни каквото поискаш.

### После:

1. Отвори `twa-manifest.json` и замени `YOUR-USERNAME` с истинското ти
   GitHub потребителско име (2 места).
2. Вземи SHA256 подписа на ключа:
   ```bash
   keytool -list -v -keystore android.keystore -alias helfi-key
   ```
   Копирай стойността до `SHA256:` и я сложи в
   `.well-known/assetlinks.json` (замества `FILL_IN_AFTER_CREATING...`).
3. В GitHub repo → **Settings → Secrets and variables → Actions** добави:
   - `ANDROID_KEYSTORE_BASE64` — резултат от `base64 -i android.keystore`
   - `ANDROID_KEYSTORE_PASSWORD` — паролата, която зададе
   - `ANDROID_KEY_PASSWORD` — обикновено същата парола
4. Push-ни промените (assetlinks.json + twa-manifest.json).
5. Пусни workflow-а `Build Android APK (TWA)` ръчно (Actions → Run
   workflow), или той ще се пусне автоматично при публикуване на GitHub
   Release.
6. Готовият `.apk` се появява като артефакт на завършения workflow run —
   свали го и го инсталирай на телефон (или го публикувай в Google Play
   по-късно).

От този момент нататък: обновяваш сайта → при нужда пускаш build-apk
workflow-а → новият APK automатично отваря обновения сайт, но пак изглежда
и се държи като нормално Android приложение.
